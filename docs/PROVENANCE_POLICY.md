# Track Mirror — Provenance Policy

Date adopted: 2026-10-23

## Repository-owner direction

The repository owner expressly directed Track Mirror development to take every reasonable opportunity to preserve material repository-owner decisions as such in the project record.

Accordingly, material decisions made by the repository owner about product behavior, architecture, UX, accessibility, licensing, commercialization, launch strategy, testing methodology, workflow, platform priorities, naming, and similar project direction should be recorded explicitly and contemporaneously when practical.

This includes, where relevant:

- the decision itself;
- the date or development context;
- whether it is a product, architecture, UX, commercialization, testing, or workflow decision;
- resulting requirements or implementation consequences.

## Attribution boundary

This policy does not treat incidental commands, typo corrections, low-level code edits, or AI-generated implementation details as independently human-authored contributions merely because they occurred under repository-owner direction.

AI-assisted research, analysis, coding, drafting, documentation, and implementation must remain separately attributable and should not be misrepresented as independently human-authored material.

When a substantive repository-owner decision leads to AI-assisted implementation, the project record should preserve both sides of that distinction: the owner decision and the AI-assisted implementation.

## Standing workflow rule

Future Track Mirror development sessions should apply this provenance rule automatically. Material repository-owner decisions should be added to the canonical development/authorship record without requiring the repository owner to request attribution again each time.
